# Agent 配置方案与生效位置

| 对象                | 保存什么                                                             | 在哪里使用                                     |
| ------------------- | -------------------------------------------------------------------- | ---------------------------------------------- |
| 连接（供应商）      | 服务地址、密钥、账号及连接所需的协议参数                             | 多份方案可以引用同一连接                       |
| 配置方案（Profile） | 某个 Agent 的连接引用、模型、行为，以及可选的 MCP、Skills 和指令选择 | 同一份方案可以应用到全局，也可以部署到多个项目 |
| 生效位置            | 全局，或独立登记的项目目录                                           | 每个位置按 Agent 分别记录一份生效方案          |

Claude Code 和 Codex 支持全局和项目位置。Claude Desktop 支持全局连接引用与原生策略，模型路由在供应商路由设置中维护。

Claude Code 和 Codex 的“新增供应商”只创建供应商，不自动创建配置方案。进入供应商或配置方案页面也不会自动生成方案。需要配置模型、行为或资源时，在“配置方案”页单独创建并选择连接。

当前开发阶段仅维护当前数据格式，不执行旧版本数据迁移、字段回填或自动补建方案。旧格式会明确报错，原文件不会被自动删除或覆盖。用户主动导入当前支持的 Agent 原生配置仍然可用。

“设置 → 应用设置”先选择 Agent，只展示其专属开关和配置目录。从 Agent 的设置入口进入时直接选中该 Agent。切换 Agent 保留尚未保存的目录草稿；保存入口会列出所有待保存目录。


## 创建、选择和应用

### 从 Agent 管理接入项目

侧栏的“Agent 管理”始终可见，负责安装、升级、卸载、版本、路径、WSL、诊断和显示开关。Claude Code/Codex 行保留“配置项目”快捷入口，可提前准备项目；该页面只显示 Profile 配置及部署就绪状态，安装和诊断在 Agent 管理页完成。Profile 菜单不再包含 Agent 管理。

Agent 配置侧栏按需显示：只有探测到已安装、且“显示”开关开启的 Agent 才出现。未安装时，“应用”页先提供安装和项目配置入口，确认安装后才显示侧栏开关；此前关闭的开关不会因重新安装而自动开启。可以关闭全部 Agent，此时从“应用”页继续管理，设置与共享资源入口仍可访问。

启动时通过纯本地版本探测判断命令行 Agent 是否存在，沿用已配置的 WSL 环境；这次探测不查询远端更新。安装、卸载及手动复查后，侧栏使用同一份结果刷新。首次探测未知的 Agent 暂不显示，复查失败保留此前已确认状态；“应用”页可重新检查。Claude Desktop 和 WorkBuddy 沿用现有应用包/配置目录探测，不以账号登录或供应商配置是否完成来判定安装。隐藏只改变界面入口，不停止 Agent 或修改项目资源。

1. 已安装的 Agent 直接复用现有安装；页面显示版本、安装路径、来源、默认路径及多处安装提示。
2. 尚未安装时，可以先登记目录、创建方案、编辑模型和选择资源库中的 MCP/Skills/提示词。安装使用原有入口，安装完成后自动复查版本、路径和来源；不会自动部署资源。
3. 在项目环境中选择已登记目录和当前 Agent 的方案，也可以分别新建方案、添加目录。这个入口只处理项目配置，不提供全局 Profile 切换。
4. Agent 可运行且检查通过后，点击“部署到项目”。安装、升级或复查期间，以及探测失败或默认程序不可运行时，项目环境中的部署和冲突覆盖确认保持禁用；仍可编辑 Profile 或取消冲突处理。
5. 手动安装或修复后，点击“重新检查此 Agent”。复查失败会保留此前显示数据供参考，同时标明状态待确认；旧版本信息不会被视为本次验证成功。

项目环境与“应用”页共用生命周期任务，离开页面不会重复安装或中断已提交的操作。升级/卸载继续使用原有确认流程；隐藏侧栏不会卸载 Agent 或移除资源。每张方案卡片提供编辑与部署操作，更多菜单提供重命名、复制、删除和重拍快照。全局 MCP/Skills 导入仍使用各自页面的原有入口；已有项目文件可按下文直接导入。

在设置中保存 Agent 配置目录后，会清除该工具旧环境的版本、安装状态、报告和错误，重新进行本地检查；旧环境的迟到结果不覆盖新状态，旧升级确认不再执行。目录保存失败则保留原状态。这个行为同样适用于原生目录与 WSL 目录之间的切换；新环境尚未确认时，不能沿用旧环境的“已安装”或“可部署”结论。

Claude Desktop 和 WorkBuddy 尚未被检测到时，“应用”页提供“前往官网下载”入口；Claude Desktop 仅在当前平台受支持时显示。此入口打开官方网站，由用户完成下载和安装。之后点击“检查更新”复查，下载页面打开不代表安装成功，也不会自动开启此前关闭的侧栏显示开关。

“可运行”表示版本探测和本机安装检查通过，不代表账号已登录、模型请求成功或 MCP 连通。WSL 版本来自现有配置指定的发行版，而安装路径报告在宿主侧探测，可能不代表 WSL 内的安装。项目部署使用 CC Switch 可访问的目录，不选择或迁移发行版，需确认 Agent 打开的确实是同一项目。其他 Agent 的项目适配与未验证的安装渠道仍在首版范围之外。

### 从“配置方案”页选择和应用

1. 进入 Claude Code 或 Codex，打开与“供应商”并列的“配置方案”页签。Claude Desktop 的配置方案仅支持全局范围。
2. 选择全局或项目位置。两处显示该 Agent 的同一组方案，超过 5 份时可按名称、模型或连接搜索。全局摘要显示当前连接、模型及方案，项目摘要显示该目录上次部署的方案。
3. 在项目位置点击“添加项目”登记目录。切换目录只改变正在查看的位置。移除登记后，目录内的文件继续保留。
4. 点击“新建方案”，填写名称，选择空白、从当前全局配置创建或从项目导入。创建后直接打开编辑器。新建对话框可直接取消，编辑器会在离开未保存的草稿时询问。
5. 在方案卡片点击“应用到全局”或“部署到项目”。例如，将同一份 Codex 方案部署到 A、B 两个目录，之后修改方案并只重新部署 A，B 继续使用上次部署的内容。Claude Code 在这两个目录的部署记录也独立保存。

查看位置按 Agent 记在本机。项目部署状态来自上次部署清单，与保存的配置比较后可显示待重新部署。项目文件手工变动和资源库内容更新在下次部署时核对，列表不会持续扫描它们。

### 连接与配置方案的独立操作

新增连接只保存接入信息，不自动生成同名方案。直接切换连接不跟随任何默认方案；需要切换模型、行为和资源时，明确应用配置方案。聚合模式的模型发布由聚合设置维护。

修改正在使用的方案或其连接后，方案显示“待应用”。重新应用后更新状态。托盘按 Agent 列出可用方案。项目目录单独登记，各目录按 Agent 分别记录部署结果。

### 导入已有项目

新建方案时，将配置来源选为“项目现有配置”，选择目录后确认。Claude Code 读取项目设置、`.mcp.json`、`.claude/skills/` 和根目录 `CLAUDE.md`；Codex 读取 `.codex/config.toml`、`.agents/skills/` 和根目录 `AGENTS.md`。模型与资源进入各自字段，其余原生行为配置保留未知字段；连接与凭据不复制进 Profile。跳过或不支持的内容会在结果中提示。

导入复用已有 MCP 解析、Skill 校验和资源保存能力，将可用内容保存为资源库记录与方案引用，同时登记导入来源目录。它不修改原项目文件、不修改全局资源启用开关，也不会自动切换供应商或部署。导入失败会保留创建表单，便于修正后重试。

导入不会把原项目文件自动登记为本工具所有。再次部署时，原样且未托管的条目或文件保留原有归属，不会仅因它们进入过 Profile 就变成可删除项；以后取消引用也不会删除这些原有内容。发生差异时仍按部署冲突规则处理，只有明确由部署写入并登记的内容，才按清单处理后续移除。

## 直接编辑与资源同步

编辑器直接读取统一资源库和所选供应商，通过四个页签组织内容。供应商负责 API 地址、密钥、账号及连接方式；模型获取使用已有连接和账号能力，Profile 不复制这些凭据。选择另一供应商只更换引用；点击“恢复供应商模型设置”才采用其模型默认值。

Claude Code 的“基本与模型”页签提供“项目 API 接入”：默认“继承全局连接”，也可选择“项目独立直连”。后者使用同一页选择的供应商，方案仍只保存供应商引用；部署时才读取其地址与凭据，写入项目的 `.claude/settings.local.json`。此选项仅影响项目部署，应用到全局仍使用现有全局应用流程。Codex 和 Claude Desktop 不显示这个选项。

项目独立直连仅支持 Anthropic 协议的普通 API Key 或 Token 供应商。项目请求直接发送到供应商，不经过 CC Switch 本地路由；需要协议转换或托管账号刷新的供应商继续使用路由能力。组织受管策略、启动参数和原生配置优先级仍然适用。供应商地址或密钥更新后，需要重新部署项目，不会实时同步。切回“继承全局连接”并重新部署，只移除本功能管理的连接字段，手写内容仍按冲突规则保护；之后请重启 Claude 会话，避免已运行进程保留项目连接环境变量。

“继承全局连接”表示撤下本功能托管的连接字段，并按 Claude Code 原生配置层级继承；如果共享项目 `.claude/settings.json` 中已有手写连接，它仍可能生效。独立直连只单独管理 API 接入，其他原生行为设置继续按配置层级叠加。

“行为与高级配置”复用原 JSON/TOML 编辑器，保存权限、沙箱、Hooks、插件及其他原生字段；Claude 快捷开关继续可用。未知行为字段保留，模型与资源已管理的字段以及连接字段不能在此重复编辑。配置格式错误会阻止保存，即使已切换到其他页签也会显示错误并提供返回入口。

模型区直接复用原供应商的 Claude/Codex 模型组件和解析、元数据逻辑，避免维护一份字段不完整的简化表单：

- **Claude Code**：主模型、Haiku/Sonnet/Opus/Fable 角色模型、显示名、子代理模型，以及各模型的 1M 标记。沿用模型获取、搜索和角色选择交互；1M 仍按模型名称后缀保存，由 Agent 与实际模型支持情况决定运行结果。
- **Codex**：沿用模型获取、搜索与批量选入、目录编辑和拖拽排序、默认模型联动、显示名/上下文/输入类型等元数据、推理档位与默认档位、自动 Review 模型和官方速度档。子代理模型、推理强度和并发上限也复用原字段。
- **Codex 运行设置**：在“推理与上下文”中编辑主模型及 Plan 推理强度、上下文窗口与自动压缩阈值；提供 1M 快捷配置。上下文、自动压缩和子代理并发字段会校验为有效整数，写入原生 TOML 数值，不能用带小数或超出范围的字符串替代。

在“资源”分区启用“管理资源”后，方案保存并应用 MCP、Skills 和指令选择，包括明确的空选择。关闭此开关，应用和部署时保留目标位置现有资源。新建空白方案默认关闭此开关。

“资源”分区按名称、ID 或描述搜索 MCP 与 Skills，显示各类已选数量；搜索仅过滤显示，不取消已选项。缺失引用仍可查看和明确移除。“指令”分区引用提示词库，并预览当前所选内容。资源与指令均沿用原有保存和部署服务。

本地已有模型设置可以离线编辑。远程获取模型需要供应商或对应账号服务可用；获取成功不会切换全局供应商或自动部署项目。

保存只更新 Profile，不切换全局配置，也不立即写项目文件。名称属于方案，目录单独登记。模型及资源选择只更新当前 Agent 的配置。选择“不使用指令模板”后再次应用，会按文件所有权规则撤下此前由 Profile 托管的指令。

编辑面板在点击顶部返回或使用 Escape 离开时，会按表单当前值确认是否存在未保存修改。选择“继续编辑”保留草稿，恢复原值后不再询问；明确点击“取消”或保存成功则正常退出。提交期间不能通过面板返回或取消重复操作。

Profile 列表、编辑所需的本地资源读取、Profile 保存/导入/部署、Agent 本地状态检查和设置保存支持离线执行。离线支持不包含获取远程模型、下载 Agent、获取远端版本或下载远程 Skill；原生 Agent 请求模型和远程 MCP 仍需要各自服务可用。

全局应用遇到缺失资源等警告时会列出明细，部分生效的方案标记为待重新应用。需要以当前实际配置更新方案时，使用卡片菜单的重拍快照操作。

MCP、Skills 或提示词的内容在统一资源库维护。项目采用一次性手动部署：每次应用读取资源库当前内容，写入所选项目；部署后由项目独立使用。资源库更新或删除不会主动改动项目，项目内的修改也不会回写资源库；需要更新时，再次应用 Profile 覆盖对应内容。不持续追踪资源版本或项目文件变化，也不提供实时同步状态。“更新为当前配置”仍可用来重拍快照，但不是直接编辑所必需的步骤。

覆盖范围是对应的 MCP 条目、Skill 目录及模型/指令内容，配置文件中的无关字段保持原样。现有部署清单用于本次部署的覆盖保护、旧托管项移除和失败恢复；遇到项目修改时仍可选择覆盖、保留或取消，具体规则见下文。

“复制方案”只需填写新名称，即可为该 Agent 生成独立方案。修改或删除副本不会修改原记录；两者仍可引用同一份资源库内容。

### Skill 仅保存到资源库

Skill 发现安装、ZIP 导入和备份恢复共用“安装到”选择，可以取消全部 Agent，选择“仅保存到资源库”。该选择会在本机保留；新技能写入资源库时不主动启用或同步到任何 Agent，随后可从项目 Profile 引用并手动部署，也可在 Skills 页另行启用。

“仅保存到资源库”不改变 Agent 的原生发现规则。如果资源库位置设为 `~/.agents/skills`，读取此统一目录的 Agent 仍可能自行发现其中技能。需要避免这种原生发现时，使用 CC Switch 自己的资源库存储位置。

## Agent 原生配置与优先级

Claude Code 的设置作用域由完整路径决定。官方区分以下三个文件：

| 完整位置                                   | 官方作用域                         |
| ------------------------------------------ | ---------------------------------- |
| `~/.claude/settings.json`                  | 用户级：影响此用户的各个项目       |
| `<项目根目录>/.claude/settings.json`       | 共享项目级：可由项目成员共享       |
| `<项目根目录>/.claude/settings.local.json` | 个人项目级：只供此用户在该项目使用 |

当前 Claude Code 项目 Profile 的设置默认写入**个人项目层**，即 `<所选项目目录>/.claude/settings.local.json`。新部署只管理这个目标文件中的受管字段；共享 `settings.json` 不属于该部署目标。共享层和用户层仍按 Claude Code 原生规则参与继承。下面表格中的 `.claude/` 均位于所选项目目录内。依据：[官方设置文件与作用域](https://code.claude.com/docs/en/settings#settings-files-and-who-they-affect)。

| 内容         | Claude Code                                                                                          | Codex                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 模型         | `.claude/settings.local.json` 的 `model` 与 `env.ANTHROPIC_MODEL`                                    | `.codex/config.toml` 的 `model`                                                                                                                   |
| 其他模型设置 | `.claude/settings.local.json` 的 `env.ANTHROPIC_DEFAULT_*_MODEL` 及 `env.CLAUDE_CODE_SUBAGENT_MODEL` | `.codex/config.toml` 的模型与 Plan 推理档、上下文/自动压缩数值、`[agents]` 子代理及并发设置；模型目录另存为 `.codex/cc-switch-model-catalog.json` |
| MCP          | 根目录 `.mcp.json`，配合项目设置中的启停规则                                                         | `.codex/config.toml` 的 `mcp_servers`                                                                                                             |
| Skills       | `.claude/skills/`，配合项目设置中的库技能启停规则                                                    | `.agents/skills/`                                                                                                                                 |
| 项目指令     | 根目录 `CLAUDE.md`                                                                                   | 根目录 `AGENTS.md`                                                                                                                                |

Codex Profile 的模型目录文件写入所选项目目录的 `.codex/cc-switch-model-catalog.json`，并在 `.codex/config.toml` 中设置 `model_catalog_json`。Codex 配置需要绝对路径的场景会写入本机绝对路径；因此将项目目录通过 Git 复制到另一台电脑后，该指针不会自动可用，需要在目标设备重新部署 Profile。Windows 下由 WSL 读取的特殊场景仍使用模型目录文件名。

Claude Code 的会话选模、`--model` 和 `ANTHROPIC_MODEL` 都会影响实际模型，只改设置文件的 `model` 字段可能被环境设置覆盖。当前项目应用在个人项目层协调模型字段与环境配置，并通过所有权、冲突预览和内容校验保护已有手写字段；会话选择、启动参数和管理策略仍遵循 Agent 原生优先级。

Codex 的项目配置层仅在受信任项目中加载，信任由 Codex 自身确认。模型、MCP 和其他配置仍遵循原生配置层级。如果同目录已有非空 `AGENTS.override.md`，它会优先于 `AGENTS.md`；应用会提示，并保留该文件。

项目应用不切换全局供应商。继承全局连接时，不向项目写入供应商地址或密钥；直连或路由模式下，模型供应商须是当前正在使用的供应商，聚合模式下可使用已加入聚合的成员。供应商当前不可用时，跳过模型更新并提示，保留项目模型现状。Claude Code 选择“项目独立直连”时，项目使用自己的供应商地址、凭据和模型，无需把该供应商切为全局当前供应商；所选供应商不存在或不支持直连时，拒绝部署并保留项目文件。

## 项目资源的控制范围

- **Claude Code MCP**：将选择的 MCP 写入项目，并通过项目 `deniedMcpServers` 规则控制资源库中未勾选、但已在全局启用的 MCP；不修改全局开关。未登记的 MCP 和更高优先级策略仍按 Agent 原生规则处理。
- **Claude Code Skills**：本机 Claude Code 2.1.326 已核验项目 `skillOverrides` 按安装目录和调用 ID 使用 `on` / `off`。这项控制只针对能明确识别的库技能；插件技能、额外原生技能、手写同名技能和上级策略仍可能加载或阻止调用。发现冲突或本地覆盖时保留用户设置并提示。

- **Codex MCP / Skills**：继续按原生全局与项目规则加载。MCP 项目项会与全局配置合并；Profile 未托管的全局 MCP 仍可能继承。勾选某项不代表隔离或屏蔽全部全局资源。

`skillOverrides` 控制技能是否可用，不改变同名技能的来源优先级。个人目录的同名技能仍可能优先于项目副本；测试技能内容变化时，请在 Agent 中核对实际加载的来源路径。

模型和启停规则的设置目标是 `settings.local.json`；MCP 定义、Skill 文件和项目指令仍使用表格列出的原生项目路径。个人项目设置并不等于把这些文件改成用户级存储，也不会排除共享层已经存在的拒绝规则。

## 凭据与项目文件

Claude Code 明确选择“项目独立直连”时，供应商地址与密钥允许写入个人项目配置 `.claude/settings.local.json`；该文件不能提交到 Git。部署时会在 `.claude/.gitignore` 添加 `/settings.local.json` 忽略规则；如果设置文件已被 Git 跟踪，则拒绝写入密钥，需先由用户处理跟踪状态。此例外只适用于独立连接部署，Profile、普通行为配置和共享项目配置不复制供应商凭据。MCP 配置仍禁止写入明文密钥、令牌、密码；普通环境变量和非敏感静态请求头并非一律禁止。

Claude MCP 可使用合法环境变量引用，例如 `env` 中的 `${MCP_TOKEN}`、请求头中的 `Bearer ${MCP_TOKEN}`，以及 URL 中支持的环境变量引用。变量值由运行 Agent 的环境提供，不要在引用的默认值中写入真实密钥。

Codex 的环境凭据应使用原生环境字段，例如 `env_vars` 转发环境变量、`bearer_token_env_var` 指定令牌变量，或 `env_http_headers` 将请求头映射到变量名称；不能把令牌本身填入这些“变量名”字段。

## 冲突、缺失资源与目录变更

应用清单记录受管内容。遇到手写内容或应用后被修改的内容时，会列出冲突路径：

- **覆盖冲突内容**：用 Profile 内容替换冲突项；配置文件中的其他字段保留。
- **保留当前内容**：保留冲突项，继续应用其余可用内容。
- **取消部署**：本次不写入项目。

资源已删除、不可读或 Skill 文件不可用时，跳过该项并保留项目现状；其他可用项继续应用。创建或保存配置时，Profile 会按 Agent 记住所选 MCP、Skill 和提示词的名称，定义仍来自资源库。资源删除后，编辑器和应用提示可显示此前保存的名称及 ID；旧 Profile 未保存过名称的引用仍显示 ID。MCP 配置不可读与资源已删除会在应用提示中分别说明。

保存其他字段不会丢弃缺失引用；取消勾选 MCP/Skill 或取消提示词选择才会移除相应引用，保存前可重新选回。资源列表中的记录不代表 MCP 已连接或 Skill 文件完整，实际文件读取检查发生在项目部署时。

冲突对话框会同时显示资源缺失或跳过提示；完成时存在提示的部署显示“项目部署已结束，请查看提示”及明细。选择覆盖文件冲突不会修复缺失资源。Profile 移除资源后再次应用，只撤下此前托管的对应内容；发现用户修改仍需处理冲突。

应用中途失败会尝试回滚；期间发生用户修改时，保留现状并报告未恢复项或备份位置。删除方案、移除登记或切换查看目录不会清理原目录中的已部署文件。项目文件是否纳入 Git 由用户决定。
