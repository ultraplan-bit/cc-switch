# 3.2 Prompts 提示词管理

## 共享资源库与分发

提示词页维护跨 Agent 共享的 Markdown 文档。一份文档可以用于多个 Agent，也可以被多个 Profile 引用。保存、编辑、删除只操作资源库，不改动已分发的文件。文件修改也不会在读取列表时自动回填到库。

从侧栏进入 **提示词**。页面的 Agent 选择用于指定分发目标；切换目标不会切换成另一份资源库。Claude Desktop 没有独立提示词目标；OpenClaw 的工作区文件继续在工作区编辑器管理。

## 创建与编辑

1. 点击 **添加提示词**，填写名称、说明和 Markdown 正文。
2. 保存到共享库。
3. 选择目标 Agent，核对页面显示的实际文件路径，再应用所需文档。

编辑已分发的文档只更新库。目标文件继续使用原内容，重新应用后才更新。删除库记录也不会删除已分发文件；引用该记录的 Profile 会提示资源缺失。

## 应用与撤下

应用会将文档内容写入目标文件。目标已有不同内容时，界面要求核对并确认覆盖；确认后若文件又发生变化，本次操作会报冲突，需重新读取后处理。不会通过后台自动备份或回填覆盖原模板。

每个 Agent 的全局目标文件一次保存一份文档。同一文档可以分别应用到多个 Agent；各次分发独立处理，失败会提示对应目标。

撤下仅清空本工具分发且未被外部改动的内容。用户手写文件、已修改文件以及配置目录变更后的其他文件不会被静默清除。撤下不会删除共享库记录。

## Agent 文件名

| Agent | 默认全局目标 |
|---|---|
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex | `~/.codex/AGENTS.md` |
| Gemini CLI | `~/.gemini/GEMINI.md` |
| Grok Build | `~/.grok/AGENTS.md` |
| OpenCode | `~/.config/opencode/AGENTS.md` |
| Hermes | `~/.hermes/SOUL.md` |
| Pi | `~/.pi/agent/AGENTS.md` |
| MiniMax Code | `~/.minimax/AGENTS.md` |

其他受支持 Agent 沿用其原生目标，页面会显示实际路径。配置目录覆盖、环境变量和账号目录可能改变目标位置。MiniMax Code 在分发时限制正文为 32 KiB；共享库本身不按单个 Agent 的限制拆分。

**Claude Code 始终按本项目约定分发到 `CLAUDE.md`；Codex 分发到 `AGENTS.md`。**

## 主动导入现有文件

选择目标 Agent，在更多菜单中导入当前文件。导入只保存到共享库，不修改源文件，也不会把源文件自动认领为可清除的托管文件。相同内容会复用已有记录，跨 Agent 无需重复复制。

若在外部编辑器修改了已分发文件，可主动导入为共享文档，再明确选择需要应用的文档。原模板保持独立。

## 在 Profile 中使用

Profile 的“指令”引用同一个共享库。项目部署目前支持 Claude Code 与 Codex，分别写入项目根目录的 `CLAUDE.md` 和 `AGENTS.md`，并沿用项目部署的冲突确认、所有权保护和回滚机制。

从当前全局配置创建或重拍 Profile 时，非空文件若没有对应的有效托管模板，会要求先主动导入并应用，避免保存错误引用。空白方案和直接编辑现有方案仍可独立选择资源。

库更新后不自动重部署项目。需要更新哪个项目，就明确对哪个项目应用方案。

## Pi 原生文档与模板

Pi 的额外入口继续管理：

- `APPEND_SYSTEM.md`：追加系统提示。
- `SYSTEM.md`：替换基础系统提示。
- 原生提示词模板：保存后在 Pi 中通过命令调用。

这些仍是 Pi 原生文件编辑功能，独立于共享文档库的保存和分发。已打开的 Pi 可在空闲时运行 `/reload` 重新加载。

## 导入导出与同步

共享文档包含在当前格式的数据库备份和跨设备同步中。恢复或同步资源库不会自动覆盖 Agent 指令文件，各设备的分发记录独立维护。

深度链接仍可导入文档；链接明确指定应用时会尝试安全分发，遇到未托管或外部修改的文件会报冲突。参见 [深度链接协议](../5-faq/5.3-deeplink.md)。
