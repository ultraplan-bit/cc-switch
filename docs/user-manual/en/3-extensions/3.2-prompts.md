# 3.2 Prompts Management

## Shared library and distribution

Prompts are shared Markdown documents. One document can be referenced by several Agents and Profiles. Creating, editing, or deleting a library entry never changes a deployed file. Reading the library never imports external file edits automatically.

Open **Prompts** in the sidebar. The Agent selector chooses a distribution target, not a separate library. Claude Desktop has no independent prompt target. OpenClaw workspace files remain in the workspace editor.

## Create, edit, and apply

1. Add a prompt with its name, optional description, and Markdown content.
2. Save it to the shared library.
3. Choose an Agent, review the displayed target path, and explicitly apply the document.

Editing a previously applied document only changes the library. Reapply it to update the target. Deleting a document leaves deployed files intact; Profiles referencing the deleted document report a missing resource.

Applying replaces the target content. If the target already contains different text, review and confirm the replacement. A further file change after confirmation causes a conflict and requires a fresh review. External contents are never silently written back into the original template.

Each Agent's global target contains one document at a time. A document can be applied independently to multiple Agents; failures identify the affected target.

Removing an application clears only content still matching the last managed write. Handwritten files, externally edited content, and unrelated files after a directory change are preserved. Removing an application does not delete its library document.

## Agent filenames

| Agent | Default global target |
|---|---|
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex | `~/.codex/AGENTS.md` |
| Gemini CLI | `~/.gemini/GEMINI.md` |
| Grok Build | `~/.grok/AGENTS.md` |
| OpenCode | `~/.config/opencode/AGENTS.md` |
| Hermes | `~/.hermes/SOUL.md` |
| Pi | `~/.pi/agent/AGENTS.md` |
| MiniMax Code | `~/.minimax/AGENTS.md` |

Other supported Agents retain their native target paths, shown in the page. Directory overrides, environment variables, and account-specific directories may change the location. MiniMax Code enforces its 32 KiB content limit during application, not during shared-library editing.

**Claude Code receives `CLAUDE.md`; Codex receives `AGENTS.md`. They are not interchangeable distribution targets.**

## Import existing content

Choose an Agent and import its current file from the more menu. Importing only adds a library document, reusing an identical existing document where possible. It does not change the file or claim it as managed content that can later be removed.

After editing a file externally, explicitly import it and choose which document to apply. The original library template remains independent.

## Profiles and project deployment

A Profile's Instructions field references the same shared library. Project deployment currently supports Claude Code and Codex, writing root-level `CLAUDE.md` and `AGENTS.md` respectively. Existing conflict resolution, ownership protection, and rollback remain in place.

Capturing the current global configuration requires a nonempty instruction file to match a managed library document. Otherwise, import and explicitly apply it first. This prevents capturing the wrong revision or mistaking existing instructions for no instructions. Blank Profiles and manual Profile editing can still select library documents directly.

Library changes do not automatically redeploy projects. Apply the Profile explicitly to each project that should receive the update.

## Pi native resources

Pi retains dedicated editors for `APPEND_SYSTEM.md`, `SYSTEM.md`, and native prompt templates. These edit Pi's own files and remain separate from shared-library saving and distribution. An already running Pi session can reload them with `/reload` when idle.

## Backup and synchronization

Shared documents are included in current-format database backups and cross-device synchronization. Restoring or syncing the library does not apply instructions to Agent files. Distribution records belong to each device.

Deep links can still import documents. An explicit application request uses the target Agent's safe application flow and reports conflicts for unowned or externally edited files. See [Deep Link Protocol](../5-faq/5.3-deeplink.md).
