# 3.2 Prompts プロンプト管理

## 共有ライブラリと配布

プロンプトは Agent 間で共有する Markdown 文書です。1 つの文書を複数の Agent や Profile から参照できます。作成・編集・削除はライブラリだけを変更し、配布済みのファイルには影響しません。一覧を読むだけで外部の編集内容が元の文書に取り込まれることもありません。

サイドバーの **プロンプト** を開きます。Agent の選択は配布先を指定する操作です。Agent を切り替えてもライブラリは共通です。Claude Desktop には独立した配布先がありません。OpenClaw の文書は引き続きワークスペースエディターで管理します。

## 作成・編集・適用

1. プロンプトを追加し、名前、任意の説明、Markdown 本文を入力します。
2. 共有ライブラリへ保存します。
3. 対象 Agent と実際のファイルパスを確認し、文書を明示的に適用します。

配布後にライブラリの内容を編集しても、対象ファイルは元の内容を保持します。更新したい対象へ再適用してください。文書をライブラリから削除しても配布先は残り、その文書を参照する Profile ではリソースが見つからないことを通知します。

対象ファイルに異なる内容がある場合は、内容を確認して上書きを承認します。確認後にファイルが再び変化した場合は競合として停止するため、再読み込み後に判断してください。外部の内容を元のテンプレートへ自動で書き戻すことはありません。

各 Agent の全体用ファイルには一度に 1 つの文書を適用します。同じ文書を複数の Agent へ配布でき、それぞれの処理結果を確認できます。

適用を解除すると、本ツールが書き込み、その後変更されていない内容だけが空になります。手書きの文書や外部で変更された内容は保護されます。ライブラリの文書自体は削除されません。

## Agent ごとのファイル名

| Agent | 既定の全体用ファイル |
|---|---|
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex | `~/.codex/AGENTS.md` |
| Gemini CLI | `~/.gemini/GEMINI.md` |
| Grok Build | `~/.grok/AGENTS.md` |
| OpenCode | `~/.config/opencode/AGENTS.md` |
| Hermes | `~/.hermes/SOUL.md` |
| Pi | `~/.pi/agent/AGENTS.md` |
| MiniMax Code | `~/.minimax/AGENTS.md` |

ほかの対応 Agent も、それぞれのネイティブな配置先を使用します。設定ディレクトリ、環境変数、アカウントごとのディレクトリにより実際のパスが変わるため、画面上のパスを確認してください。MiniMax Code の 32 KiB 制限は適用時に検証し、共有文書の保存自体はその制限に依存しません。

**Claude Code への配布は `CLAUDE.md`、Codex への配布は `AGENTS.md` です。両者を混用しません。**

## 既存ファイルの取り込み

対象 Agent を選び、メニューから現在のファイルを取り込みます。取り込みはライブラリへの保存だけを行い、同一内容の文書があれば再利用します。元ファイルは変更せず、後から消去できる管理対象として自動登録することもありません。

外部エディターで配布済みのファイルを編集した場合も、必要な内容を明示的に取り込み、適用する文書を選び直します。元の共有テンプレートは独立して保持されます。

## Profile とプロジェクトへの配置

Profile の「指令」は同じ共有ライブラリを参照します。プロジェクトへの配置は現在 Claude Code と Codex に対応し、プロジェクト直下の `CLAUDE.md` と `AGENTS.md` へそれぞれ書き込みます。既存の競合確認、ファイルの管理範囲、失敗時の復元処理を引き続き使用します。

現在の全体設定から Profile を作成・更新する際、空でない指令ファイルが管理中の共有文書と一致しなければ、先に取り込みと明示的な適用が必要です。誤ったリビジョンを保存したり、既存の指令を「指令なし」と扱ったりすることを防ぎます。

ライブラリの変更はプロジェクトへ自動配布されません。更新したいプロジェクトへ Profile を再適用してください。

## Pi のネイティブ機能

Pi の `APPEND_SYSTEM.md`、`SYSTEM.md`、ネイティブなプロンプトテンプレートは専用画面で引き続き編集できます。これらは Pi のファイルを直接編集する機能で、共有ライブラリの保存・配布とは別です。起動中の Pi では、アイドル時に `/reload` で読み込み直せます。

## バックアップと同期

共有文書は現在形式のデータベースバックアップとデバイス間同期に含まれます。復元や同期だけでは Agent の指令ファイルに書き込みません。全体用ファイルへの配布記録はデバイスごとに管理します。

ディープリンクからの文書取り込みも利用できます。リンクが適用を明示的に指定する場合は、対象 Agent の安全な適用処理を実行し、未管理または外部で変更されたファイルがあれば競合を報告します。[ディープリンクプロトコル](../5-faq/5.3-deeplink.md)を参照してください。
